# termo.api

Generated by `tools/gen-api-doc.sh` from the tables in `src/lua/*.c`; do not edit by hand.

`termo.api` is the flat C surface the Lua runtime (`runtime/lua/termo/`) builds on. Handles are tmux ids as strings: `$1` a session, `@2` a window, `%3` a pane. Reading state is evaluating `#{}` formats; changing it is running commands. Every function returns without waiting; one that needs to wait takes a callback.

## Where commands run

`cmd(string)` follows the same rule as hooks:

- inside a running command (a key binding, `run-lua`, `init.lua`, a hook): the commands are queued right after it, in the order of the calls, and nothing is returned;
- inside an event handler or a menu, prompt or popup callback: the commands are queued on the client's queue and run once the core is back in its loop; nothing is returned;
- from a timer or a `system` callback: the commands run now and `output, error` come back. A command that has to wait (`run-shell`, `display-popup`) returns `nil, "asynchronous command, use cmd_async"`; when something else is already waiting on the queue the error is `"command queue busy, use cmd_async"`.

`cmd_async(string, fn)` works everywhere and calls `fn(output, error)` when the commands have finished.

## Budget

Lua runs inside the server's single event loop. A call from a key, `run-lua` or a timer may take 2 seconds; an event handler or a status line variable 50 milliseconds. Past that the call is cut with an error, reported to the client that caused it or to `show-messages`.

## Changing state

### `termo.api.set_option`

```lua
set_option(name, value[, target])
```

Set an option, parsed like set-option; a table sets an array.

### `termo.api.cmd`

```lua
cmd(string) -> output, error
```

Run commands; inside a command, event or UI callback they are queued and nothing is returned, from a timer they run now.

### `termo.api.cmd_async`

```lua
cmd_async(string, fn(output, error))
```

Run commands and call fn with their captured output when done.

## Events

Call fn with a table of the payload each time event fires; any hook name, or a @custom one.

### `termo.api.emit`

## Time and processes

### `termo.api.defer`


Call fn once after ms milliseconds; the timer has stop().

### `termo.api.timer`


## Status line

### `termo.api.format_add`

```lua
format_add(name, fn(name) or nil)
```

Define #{name} for status lines and formats; fn returns the value and may call eval() for the target being drawn; nil removes it.



## The Lua side

`init.lua` (`runtime/lua/termo/init.lua`) exposes the same functions as `termo.cmd`, `termo.on` and so on, plus:

- `termo.keymap.set(key, rhs)`, `set(table, key, rhs, opts)`, `del`, `root(key, rhs)`;
- `termo.opt.name` reads and writes options, underscores standing for dashes; `termo.opt.of(handle)` for a session, window or pane;
- `termo.ui.menu`, `popup`, `message(fmt, ...)`, `prompt`, `confirm(question, fn)`;
- `termo.format.add(name, fn)` and `del(name)`;
- `termo.json.encode` and `decode`;
- `termo.layout.apply(spec, {target, done})` for declarative splits;
- `termo.hints.mode(name, spec)` and `setup()` for modal key tables with a hint bar;
- `termo.palette.add`, `open`, `setup{key}` for a fuzzy command palette;
- `termo.float.new`, `toggle`, `move`, `setup{keys}` for floating panes;
- `termo.pack.setup{...}`, `load(dir)`, `update()`, `list()` for plugins with a `termo.json` manifest.

`run-lua -j 'return termo.api.list_panes()'` prints JSON, which is how other languages use the same API from outside the server.
